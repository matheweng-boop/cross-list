# Putting Cross List online (Render)

The app runs as one Docker container on Render, with a 1 GB disk for the database.
Cost: Render "Starter" web service (about $7/month) plus the disk (about $0.25/month).
Every push to the `main` branch on GitHub redeploys the site automatically.

## One-time setup (about 10 minutes, works from a phone)

1. Go to <https://render.com> and **sign up with GitHub** (allow access to the `cross-list` repository).
2. In the dashboard choose **New → Blueprint** and pick the `cross-list` repository.
   Render reads `render.yaml` and shows one web service called `cross-list`.
3. Render asks for the values it cannot make up:
   - `CROSSLIST_SITE_PASSWORD`: the password you will type to open the site. Use a long one.
   - `CROSSLIST_DIGIKEY_CLIENT_ID` / `CROSSLIST_DIGIKEY_CLIENT_SECRET`: from developer.digikey.com
     ("Product Information V4"). Leave empty to switch pricing off; you can add them later.
   `CROSSLIST_SECRET_KEY` is generated by Render.
4. Click **Apply**. The first build takes a few minutes; the first start loads all parts (about 15 s).
5. Open the address Render shows (like `https://cross-list-xxxx.onrender.com`) and sign in.

## Later

- **Change the password or DigiKey keys:** Render → cross-list → Environment. Saving restarts the site;
  a new password signs every browser out.
- **New data or features:** pushed to GitHub, deployed by Render. Changed data files are loaded on start;
  your FFF review decisions and cached prices are kept.
- **Switch off values from unofficial datasheet copies** (marked † in the pages, files in `data/real/unofficial/`):
  Render → cross-list → Environment → add `CROSSLIST_USE_UNOFFICIAL_DATA` = `false` and save. The restart reloads
  the data without them, so every such value leaves the database. Set it back to `true` (or delete it) to restore.
  Deleting the `data/real/unofficial/` folder and deploying has the same effect, permanently.
- **Own address** (e.g. `crosslist.example.com`): Render → cross-list → Settings → Custom Domains.
- **Region:** `render.yaml` uses Frankfurt; change `region` before the first deploy if another is closer.
- **Backups:** Render keeps daily snapshots of the disk (Render → cross-list → Disks).

## What runs where

| Item | Where |
| --- | --- |
| Code, rules, parts data (`data/real/*.yaml`), pad data | GitHub, built into the image |
| Database: FFF reviews, cached DigiKey prices | Render disk at `/data` |
| Password, secret key, DigiKey keys, inbox key | Render environment variables (never in the code) |

Run the same image locally: `docker build -t cross-list . && docker run -p 8000:8000 -v $PWD/var:/data cross-list`.

## Daily update run (comments pulled automatically)

A scheduled Claude session reads everything said on the site once a day through `GET /api/inbox`, which needs its
own read-only key, never the site password.

1. Make a long random key (for example 40 letters and digits from a password manager).
2. Render → cross-list → Environment → add `CROSSLIST_INBOX_TOKEN` = the key, and save (the service restarts).
3. Claude cloud environment settings (the environment menu in the session's title bar → Edit):
   - Network secrets → Add secret: host = the site's host (`<service>.onrender.com`), header `Authorization`, value
     `Bearer <key>`. The environment adds it to requests for that host; the key never enters a session. (Without
     network secrets: the environment variable `CROSSLIST_INBOX_TOKEN` = the key.)
   - Environment variable `CROSSLIST_SITE_URL` = the site's address (`https://<service>.onrender.com`).
   - If the network access level is limited, add that host to the allowed domains.
4. The run follows `docs/daily_update.md`. Without the key the inbox is closed (HTTP 404) whenever the site has a
   password; with a wrong key it answers 401. Change the key in both places to revoke it.
