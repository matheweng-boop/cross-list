Matching rules

Priority groups per product family (edit rules/*.yaml). Priority 1 must be equal or better for a functional match; priority 2 and 3 are shown for information and never block a cross. Hard parameters define what the part does.

How a cross type is decided
  • Same package – same body length, body width, lead span and pitch. The pin count may differ: a position without a pin counts as a no-connect. Pin-to-pin – same package and the same function on every pin.
  • FFF (form, fit & function) – pin-to-pin and every priority 1 parameter equal or better (better ones are marked): an exact drop-in.
  • Upgrade – every priority 1 parameter equal or better, at least one better, in another package or pinout; a smaller package counts unless the reference is package-locked.
  • Functional equivalent – priority 1 met, but another package or pinout.
  • Package equivalent – same package, different features; marked pin-to-pin or not.
  • Downgrade – pin-to-pin, with a priority 1 value lower than the reference.
  • Anything else is not listed. Obsolete / NRND / last-time-buy candidates are always listed last.
